# A10 follower 发送频率对照

先结束模型推理。保持控制台打开，机器人处于已使能、跟随未运行的状态，在 `fluxvla` 环境运行：

```bash
python scripts/a10_follower_frequency_test.py
```

默认实验：第4关节从启动位置增加5°，其他关节目标保持启动位置。
分别以30、60、120Hz持续发送同一个绝对目标。每轮以固定60Hz回到同一起点后再测试下一频率。
去程和回程均等待六轴误差不超过0.2°、反馈速度不超过0.5°/s并持续0.3秒。
每个阶段默认最多8秒，状态查询保持50Hz，不随发送频率变化。
目标是角度阶跃，不是按频率加快播放一条轨迹；这能单独测量 follower 对重复发送频率的响应。

脚本复用控制台的共享连接；没有共享服务时会自行启动并在测试结束时关闭。
不需要模型服务、相机或USB夹爪。不会使能、初始化、切换坐标系或抢占其他会话的跟随。
运行前选定允许这5°往返的姿态和关节。Ctrl+C、状态失效、控制器故障或到位超时会结束发送，尝试停止跟随；异常时不自动回位。

调整关节、幅度、频率或重复次数，例如：

```bash
python scripts/a10_follower_frequency_test.py --joint 4 --delta-deg 3 --rates 30 60 120 --rounds 2
```

允许幅度为0.5°至10°，正负均可；发送频率为1至240Hz。
输出目录为 `work_dirs/a10/follower_tests/<时间>_follower_frequency/`：

- `sends.csv`：每次发送的六轴目标（度）、请求频率、计划时刻、实际开始/结束时刻和迟到量。
- `states.csv`：每次回复的六轴实际角度、控制器内部目标 `motor_pos`、最近发送目标及查询开始/接收时间。
- `events.jsonl`：完整控制器state、阶段开始/结束、发送记录和异常。
- `comparison.json`：各频率去程的实测发送频率、90%位移耗时、稳定到位耗时、采样峰值关节速度、误差和跳过的发送时隙数。
- `metadata.json`、`summary.json`：参数、版本信息和日志丢弃/写入错误统计。

比较同一关节、同一起点、同一位移的 `time_to_90pct_s` 和 `settled_s`。
后者包含0.3秒稳定观察时间；峰值速度由相邻状态差分得到，受采样噪声和回复时延影响。
采样时间是本机收到回复的时间，未宣称与控制器采样时刻同步。
本地发送成功不等于UDP收到或实际到位；只有实际反馈用于判定到位。
如果未达到90%位移则该指标为空，异常或日志不完整时 `comparison_valid=false`，不据此作完整对照结论。
